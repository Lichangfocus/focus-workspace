版本：0.1-draft，修订 8。状态：第一期为对话与 Harness 管理，完整模块按[功能清单](features.md)分期；Demo 仍为修订 3 的实现。下文描述各模块完整行为，“首期”指该模块首次交付，不代表全部纳入 v0.1。

P1 主要入口是对话与 Harness，设计详情见[第一期设计](harness-management.md)。对话覆盖资料、执行、人工控制、成果和历史；Harness 覆盖 Tool、Skill、MCP 等装配与真实现状、配置应用及手动回退。首个本地账号与必要设置作为基础；插件桌面 P2、小组件 P3，多账号管理界面建议 P2。


## 首页

首页的最新定义为“输入框 + 同页插件桌面”，桌面不划分项目、文件夹或多桌面层级；桌面内容统一按插件承载，目前支持文件/网页快捷方式和定时任务小组件；通用安装方式后续定义。首页“添加”把组件开发 Skill 带入输入框，生成的特殊组件可从产物中 Pin 到首页，任务每次完成后更新前端数据。完整功能、联动、状态与待定项见[首页功能定义](home.md)，这是首页需求的唯一详细来源。

用户已明确上述结构、插件形态与开发路径；输入框细节、调度策略和默认插件集合仍是建议稿。第 3 张方向稿保留为视觉参考，原固定右侧任务区与文件夹式桌面不再作为结构约束；Demo 尚未调整。

## 能力广场

第一期的本地能力装配并入 Harness，包含 Tool、Skill、MCP 与已有 Subagent 预设；不单独设计重复的能力管理页面。具体操作与权限见[第一期设计](harness-management.md)。复杂 Subagent 编辑及高级依赖管理安排 P2；长期能力发现、共享、市场和分发方式仍后置。

## Harness 设置

P1 展示当前实际装配的模型、指令、Tools、Skills、MCP、Subagent、权限与会话关联，结合关系视图和清单，区分配置与实际加载状态。配置经过编辑草稿、校验、查看差异、应用及运行检查，失败保留可用配置；支持版本追溯与手动回退。详细行为由[第一期设计](harness-management.md)维护。

P5 才加入任务反馈生成优化建议、固定任务 A/B 和评估结果；这些不影响 P1 的配置应用与回退。可视化现状不等于可任意拖拽编辑 Agent 执行流程。

## 知识库

提供来源、Wiki、图谱三个视图，可限定工作空间或账号通用范围。首期支持 UTF-8 Markdown/纯文本工作空间资料及本产品会话；其他类型显示不支持，不静默跳过。

导入显示来源列表、读取范围、进度和失败项。用户预览后授权；默认不递归导入隐藏目录、依赖产物和凭证文件。目录导入建立受控来源引用及快照，整理器不改写原文件。

生成内容先进入待审阅区，显示建议、原文片段和变更，确认后进入可检索 Wiki。实体、关系关联证据，同名实体可合并，错误关系可删除。重新生成采用差异审阅，保留手工编辑和历史版本。

来源变化后显示“待更新”；移除或撤销权限后，相关派生知识立即停止向新任务提供，并标记受影响的 Wiki。历史任务引用保留审计记录，彻底删除敏感内容须显式清理历史与备份。

Agent 查询返回摘要、来源定位及版本，必要时再读原文，不把整个知识库一次性加入上下文。检索必须经过账号及工作空间范围过滤。

## 协同

协同阶段先提供自己的 Agent 名片，创建协作对象记录和任务草稿。名片说明职责及可接受任务，不能包含凭证或默认共享整个知识库；联系人记录不等于已连接的真实对方。

通信功能的流程为：确认对方身份与能力 → 选择任务和共享材料 → 审阅并发送 → 对方接收或拒绝 → 跟踪状态 → 接收带来源的结果。发送、重试、超时与取消都有记录，重复消息不能触发重复执行。

对方内容按外部输入处理，无权直接读取本地文件、调用连接器或修改 Harness。接受任务后只在该次协作授权范围内执行；断网时显示真实状态，不伪造已送达或已完成。

## 账号入口

首次启动创建本地账号，再选择模型和工作空间。允许跳过模型配置先浏览工作台，执行任务前再提示配置。设置支持切换账号、查看数据目录、导出、备份和恢复。

切换账号先等待当前任务结束或由用户停止，再关闭当前运行时及订阅，新账号启动独立环境。首期不支持多个账号同时后台执行。

## P1 受控改进的交互

修订 8 让成果反馈与 Harness 候选关联：用户从结果处选择“改进做法”，进入候选差异与验证结果，决定采纳或拒绝；版本历史能回溯来源及回退原因。入口详细行为见[第一期设计](harness-management.md)，效果定义见[自进化设计](self-evolution.md)。当前 alpha.2 尚未实现该链路。
