## 身份

账号使用稳定随机 ID，名称仅用于展示。设备 ID 表示安装设备，Agent ID 表示账号拥有的执行主体，Subagent 实例和会话各有独立 ID。未来绑定云账号时增加映射，不覆盖本地归属标识。

本地账号不要求云注册，也不借用 DSH 匿名遥测 ID。账号之间提供应用级隔离，不承诺操作系统账号级安全；具有同一系统用户文件访问权的人可能访问本地数据。

## 归属规则

| 对象 | 归属与访问规则 |
| --- | --- |
| 工作空间 | 属于账号，绑定授权目录和项目指令；知道路径不等于获得读取权 |
| 任务与 Session | 属于账号，可关联工作空间；DSH session ID 与产品任务 ID 映射 |
| 成果与桌面布局 | 属于账号；成果关联任务及文件，布局只保存插件放置及对象引用 |
| 桌面插件与输入草稿 | 插件配置、显示状态、排序、草稿和引用归当前账号；插件展示业务对象不复制归属或扩大权限；安装机制待定 |
| 文件 / 网页快捷方式 | Pin 记录属于账号，引用目标及来源产物；取消 Pin 只删除首页引用，不删除目标 |
| 小组件与定时任务 | 组件定义和版本、开发 Skill 引用、关联开发会话、调度计划、授权范围、运行记录及输出数据均归当前账号；Pin 状态与计划启用状态独立 |
| Skill、连接器、Subagent 配置 | 安装及配置属于账号；共享程序资源不包含个人秘密 |
| 模型及连接器凭证 | 按账号及服务隔离，优先使用系统凭证存储，界面仅显示掩码 |
| Harness 版本 | 属于账号；任务绑定实际版本并保留能力快照与验证记录 |
| 任务反馈、改进候选、评估及采用记录 | 属于账号，默认限来源工作区；保存来源任务、反馈、基准和候选版本、验证与采用/拒绝/回退依据，不自动跨项目共享 |
| Wiki、来源、实体与关系 | 属于账号，标明工作空间或账号通用范围；关系关联证据 |
| 联系人与协作 | 属于账号；另行记录共享对象、材料、授权范围和有效状态 |

主进程根据当前账号解析请求，调用方不能单凭传入 account_id 读取另一账号。列表、搜索、图谱、缓存、附件、运行事件和后台索引遵循相同范围，不能只靠界面隐藏实现隔离。

## 存储建议

安装目录仅保存程序与默认资源。系统应用数据目录保存账号索引，各账号使用独立数据库、DSH home、日志、知识快照、附件和配置版本。设置 DSH home 后仍须验证每个插件的实际持久化路径，不假设都会自动隔离。

alpha.2 当前以原子 JSON 保存产品配置，SQLite 是后续复杂查询的备选，P1 不预建完整知识系统。任务反馈、候选和评估的最小字段见[进化基础](../../engineering/evolution-foundation.md)。后续产品 SQLite 可保存业务关系与 Wiki 版本；DSH 会话事件是执行事实来源，产品只保存映射及可重建索引，不另写冲突的会话历史。知识正文可导出 Markdown，关系首期保存在关系表，无需额外部署图数据库。

来源记录账号、工作空间、路径或会话定位、版本及授权；派生内容记录引用片段、生成时间、模型和审阅状态。人工编辑记录作者类型，避免自动生成覆盖。

## 导出、删除与恢复

账号导出包含可迁移业务资料、知识与配置，也包含快捷方式、组件定义、调度计划及可迁移的数据记录；默认不含明文凭证，恢复后重新授权。建议恢复的小组件计划先保持暂停，核对数据来源和时间设置后再启用，避免把恢复过程当成启动任务。导入遇到账号 ID 冲突时选择恢复原账号或创建新账号，不能自动合并。

删除来源先停止索引和后续检索，再按策略清理派生内容。删除工作空间默认仅清除元数据及授权，不删除用户原始目录。删除账号须确认范围，并处理运行任务、索引、凭证和备份保留。

数据升级前创建一致性备份，记录应用、DSH、配置及数据格式版本。恢复到独立目录验证；旧应用遇到不兼容新数据应拒绝加载，提示恢复配套备份。Git 回退不能代替用户数据恢复。

## 进化记录的作用域

用户反馈与 Agent 推断分开保存，只有用户明确选择才提升为账号通用做法。候选不得读取未授权工作区；发布可共享 Skill 或插件时另外确认材料与范围，不把个人任务日志、凭证或隐含私域内容默认写入共享包。删除来源后标记证据失效，并停止后续改进任务对其使用；原版本和评估引用保留可解释的缺失状态。

## 账号入口

首次启动创建本地账号，再选择模型和工作空间。允许跳过模型配置先浏览工作台，执行任务前再提示配置。设置支持切换账号、查看数据目录、导出、备份和恢复。

切换账号先等待当前任务结束或由用户停止，再关闭当前运行时及订阅，新账号启动独立环境。首期不支持多个账号同时后台执行。

## 设置与模型目录

首次使用建立稳定的本地账号 ID 和显示名称；模型、工作区、会话、成果引用、能力配置及进化记录都属于该账号。项目反馈默认留在项目内，只有明确选择才提升为账号通用做法。

设置提供模型连接、必要权限和数据目录入口。凭证独立保存，普通任务、候选、评估和日志索引只记录引用，不回显密钥。首期提供可操作的退出后备份和兼容恢复步骤；多账号切换及完整导入导出管理在后续实现。

模型目录维护（SETTINGS-01，2026-09-23 已获局部更新授权）：选择器直接展示模型名称和实际发送的 model ID，兼容转接信息紧邻该入口；这不表示本地能独立验证服务端权重版本。对齐 DeepSeek 官方公开 API；主要入口为 `deepseek-flash`，显示 DeepSeek-V4.1-Flash。保留 `deepseek-v4-pro` 以兼容已有选择，明确标注当前转接 V4.1-Flash，不再描述为更强的独立模型；不把已退役别名或尚未发布型号列为新增模型。模型 ID、已有会话和用户连接设置保持兼容。依据：[官方发布说明](https://api-docs.deepseek.com/news/news260910/)、[官方模型列表](https://api-docs.deepseek.com/zh-cn/api/list-models/)。本项不代表整合方案或自进化功能已获开工确认。
