## 已确定的页面结构

首页由一个输入框和一个桌面区域组成，两者直接放在同一个页面。桌面区域内的内容统一是插件。首页不设桌面、项目、文件夹的导航层级，不需要进入下一层页面才能开始工作。插件种类可以持续补充，目前明确支持文件或网页快捷方式，以及由定时任务驱动的小组件。首页设“添加”入口，点击后将开发 Skill 带入输入框，用对话开发可 Pin 到首页的特殊组件。通用插件安装、分发和升级方式留待后续定义。

上述结构与创建方向为用户已明确内容；下文的默认行为、状态、调度管理和验收细节为补充建议，不代表首期全部实现范围已获批准。第 3 张方向稿继续作为视觉参考，但其中固定的右侧任务区、文件夹式桌面不再是首页结构约束。

## 首页要完成的事

用户在输入框表达目标，通过桌面插件查看当前工作、操作资料、使用成果，再把相关内容交回 Agent 继续处理。输入框是统一任务入口；插件既可以是打开文件或网页的快捷方式，也可以是直接展示数据和提供操作的小组件。

主导航和账号入口属于应用外壳，不构成首页内的业务层级。任务涉及的工作空间仍是资料范围，可在需要时选择，不要求先建项目、进入文件夹或切换桌面。这里的“无层级”约束首页的组织和导航，不强制抹平插件所处理资料本身的结构。

## 输入框（HOME-01）

| 功能 | 建议行为 |
| --- | --- |
| 添加组件 | 点击首页“添加”后聚焦输入框，附带明确可见的组件开发 Skill 和创建意图；用户描述需求后开始开发，不另起独立搭建器 |
| 表达任务 | 多行文字输入；支持粘贴；明确发送按钮；空内容不提交 |
| 引用上下文 | 添加文件或引用桌面插件中的具体内容，以可移除的引用项展示来源和范围；粘贴文件路径不自动授权读取 |
| 任务范围 | 默认使用当前账号；需要目录、项目知识或能力时再选择，提交前能查看当前选择；不把全部插件内容默认塞入模型上下文 |
| Agent 配置 | 显示当前可用的 Agent/模型及能力组合，用折叠选项查看或切换；复杂配置进入对应模块 |
| 新任务与继续 | 默认发起新任务；从插件点击“继续处理”时明确显示正在继续哪项任务，允许改为新任务 |
| 草稿 | 输入文字和未提交引用暂存；切页返回不丢失；按本地账号分别保存 |
| 发送与反馈 | 提交后马上显示对应任务及状态；失败保留原文和引用，防止重复点击造成重复任务 |
| 运行中输入 | 可继续编辑草稿；补充到当前任务与另开任务要明确区分。首期建议每个账号先支持一个执行中任务，新的独立任务提示等待或停止当前任务，多任务并行另行确定 |

布局建议保留方向 3 的底部输入框，桌面占主体空间；具体位置、高度和是否可收起留到下一步样式对齐，不是已确认约束。输入框和插件展开内容不能互相遮挡主要操作。

## 桌面区域（HOME-02）

桌面是平铺插件的同一块区域。不内置文件夹、分组层级、多桌面切换，也不要求所有插件都长成文件图标。插件可以呈现列表、卡片、文档、图表或工具面板；这些是插件内容，桌面只负责放置和使用它们。

| 功能 | 建议行为 |
| --- | --- |
| 添加 | 首页始终提供“添加”入口，将组件开发 Skill 带入输入框；常规开发通过对话完成 |
| 展示 | 快捷方式显示名称、类型及打开入口；小组件直接显示最近一次有效数据和更新状态，保留同页平铺结构 |
| Pin | 文件、网页或开发完成的小组件可在产物等场景中“Pin 到首页”；首页显示对应入口或组件 |
| 直接操作 | 常用操作在插件内完成，例如打开成果、勾选待办、继续任务；插件操作结果及时更新 |
| 调整位置 | 拖动排序，另提供不依赖拖动的前移/后移操作；布局按账号保存 |
| 调整占用空间 | 支持收起和展开；复杂内容可在本页临时放大或预览，关闭后回到原位置。自由缩放尺寸作为待定增强项 |
| 显示管理 | 已有插件可隐藏并恢复；隐藏不等于卸载，不删除插件数据，也不自动停止任务。后续安装方案确定前，Demo 可用预置插件表达这条链路 |
| 查找 | 插件较多时按名称定位或过滤桌面上的插件；不默认进行全知识库搜索 |
| 独立加载 | 插件分别显示加载、空内容、错误及重试状态；一个插件失败不阻塞输入框和其他插件 |
| 布局恢复 | 重启后保留排序和显示状态；提供恢复默认布局的操作，只改变布局，不清除业务数据 |

## 插件的最小定义（HOME-03）

桌面插件是放在首页、供用户查看或操作某类工作内容的功能单元。这是产品概念，暂不规定安装包格式、运行环境或是否直接对应 DSH 插件。

一个插件至少要定义：它解决什么问题、显示什么数据、支持哪些操作、如何与输入框联动，以及加载失败时怎样恢复。产品需记录其稳定标识、显示名称、当前账号、配置和布局状态。是否支持同一插件放置多个实例，后续随实际使用场景确定。

插件只能使用当前账号授权的资料。它显示一份文档，不代表这份文档已经传给 Agent；用户选中“交给 Agent”后，输入框显示引用及待发送指令，再提交执行。插件也不能因出现在桌面上就自动获得文件、连接器或外部发送权限。

桌面插件提供用户可见的功能；Skills、连接器和 Subagent 提供 Agent 的执行能力。两者可以关联，但不是相同概念。DSH 的底层插件是技术实现机制，此阶段不确定三者的一一映射或安装入口。

## 当前插件形态

这两类是当前明确的形态，不是封闭分类；以后可持续增加插件种类。上一轮的任务、资料、成果、待办和知识面板仅是可选场景，不要求预先固化成首页默认插件集合。

| 形态 | 内容与使用方式 | 产生方式 |
| --- | --- | --- |
| 文件 / 网页快捷方式 | 保存目标引用，在首页显示入口；点击后预览或打开目标 | 在成果预览、文件操作或网页产物等场景触发“Pin 到首页” |
| 定时任务小组件 | 后台按计划执行任务，产出数据后由前端及时渲染，首页持续显示最近结果 | 首页“添加”带入开发 Skill，通过对话生成特殊组件，预览后 Pin 到首页 |

## 文件与网页 Pin（HOME-05）

用户可在文件、网页或产物详情中选择“Pin 到首页”。Pin 的是目标引用，不把文档内容或网页副本复制成一个新业务对象，也不自动产生定时任务。普通网页快捷方式与带调度的小组件分别识别，不因文件扩展名或 URL 自动判断为可执行组件。

建议快捷方式保存名称、目标类型、文件引用或 URL、所属账号，以及可获得的来源任务/产物标识。Pin 后给出成功反馈并可定位首页入口；同一目标再次 Pin 时定位已有入口，避免无意重复。目标重命名、移动或删除后提示失效并允许更新引用，不能把缓存内容伪装为有效目标。

取消 Pin 只移除首页入口，不删除原始文件、网页、成果或历史任务。文件和网页的具体打开方式可随桌面平台和预览能力进一步确定。

## 添加与 Skill 开发（HOME-06）

已确定的主链路：**首页添加 → 输入框带入 Skill → 描述需求并开发 → 生成特殊组件 → Pin 到首页**。这里定义的是从工作中创建组件的路径，不要求先设计插件市场或安装包流程。

建议的交互步骤：

1. 点击“添加”，回到同页输入框并显示已附带的“首页组件开发”Skill；该名称暂定，实际实现与版本后续确定。已有未发送草稿先保留，不被静默覆盖；取消创建可以退出该模式。
2. 用户描述组件要做什么，例如“每天上午整理项目待办，在首页显示需要我处理的三件事”。Skill 引导补齐数据来源、运行频率、输出内容和展示方式。
3. Agent 开发组件，形成可识别的“首页小组件”产物。产物同时说明执行任务、调度计划、输出数据与前端展示方式，不是只有一张 UI 或一段孤立代码。
4. 在产物中预览组件，并试跑一次任务，验证结果能被正确渲染。若使用样例数据，要明确标注，不能将样例预览称为已经接通真实来源。
5. 开发完成后提供“Pin 到首页”，保存组件引用、名称及展示位置。Pin 与定时任务启用状态分别展示；建议在首次固定时让用户看清频率和使用的数据范围，并明确是否启用计划。
6. 后续从组件“修改”回到输入框，带入同一 Skill、组件引用和已有定义继续开发；建议先预览新版本，再替换当前使用版本，并保留恢复旧版本的入口。

Skill 负责引导与开发，持续运行由定时任务承担，前端负责渲染任务产出的数据。三者关联记录，Skill 本身不被视为定时调度器。具体代码结构、渲染接口和插件执行机制留待工程方案确定。

## 定时任务与数据渲染（HOME-07）

每个此类小组件都关联一个定时任务定义。基本链路为：**到达计划时间 → 执行任务 → 保存本次输出数据 → 更新前端展示**。用户所说的实时渲染在这里定义为任务完成后及时呈现新数据，不默认承诺上游数据持续推送或任务运行中每一步都刷新。

建议将下列信息纳入组件定义与管理：

| 内容 | 定义与建议行为 |
| --- | --- |
| 执行任务 | 目标、数据来源、允许使用的能力和预期输出；每次运行可回看状态及来源 |
| 调度计划 | 频率、时间、时区、启用状态、下次运行时间；允许暂停、恢复和手动立即更新 |
| 数据输出 | 保存带运行标识、生成时间和组件版本的结果；前端消费明确的数据字段，不在每次打开首页时重新执行完整任务 |
| 展示定义 | 名称、布局、数据字段与操作；已有结果可直接展示，生成逻辑和展示逻辑分开维护 |
| 首次无数据 | 显示等待首次运行或引导试跑，不伪造结果 |
| 正在更新 | 保留最近一次成功结果，同时标记更新中，避免内容反复清空 |
| 成功 / 失败 | 成功后更新数据和时间；失败显示原因与重试，保留旧结果并明确它不是本次更新结果 |
| 暂停 | 显示已暂停与最后更新时间，不暗示数据还在自动更新；仍可查看已有结果 |
| 隐藏 / 取消 Pin | 只改变首页显示，不等于暂停或删除任务；操作时提示任务当前是否仍启用，并提供单独暂停入口 |

本地调度只在可用的执行环境中运行。电脑休眠、应用完全退出或账号切换后，不能承诺继续执行或准时更新；后台驻留、漏跑补偿、重试和并发策略在工程方案中定义。在这些规则确定前，不将调度开关等同于已经实现可靠后台运行。

原首页“单个前台任务”的建议不直接套用于后台小组件；两者的排队和资源竞争需要单独设计。同一组件的重叠执行如何处理尚待确定，但较早运行的晚到结果不能覆盖较新的有效结果。切换账号后的数据和事件沿用账号隔离规则。

## 任务与成果的完整链路

1. 用户输入目标，可从桌面插件选择具体资料作为引用；提交前能看到本次任务范围。
2. 发起任务后，任务与对话插件在同一首页显示输入、过程和流式回复。若该插件被隐藏，自动恢复显示并定位该任务，避免提交后找不到反馈。
3. 需要补充资料或授权时，任务显示“等待用户”，在对应插件中回答、允许或拒绝。输入草稿不会因授权操作被清空。
4. 执行中可停止；停止不承诺撤销已经发生的文件修改或外部动作。失败和中断说明已完成的部分，重试不得默认重复外部写入。
5. 完成后在任务中给出结果，成果插件显示同一份成果的引用，不复制出一份无关联结果；成果插件隐藏时仍可从任务中打开结果。
6. 用户可将文件或网页成果 Pin 为首页快捷方式；组件开发产物则 Pin 为可展示数据的小组件。点击成果“继续修改”，输入框带上成果和任务引用，用户补充要求再发送。需要沉淀知识或改进 Harness 时，带着该任务进入对应模块。

任务状态沿用 TASK-01：排队、运行、等待用户、已停止、完成、失败、中断；是否启用排队取决于并发方案。首期成果类型沿用 ARTIFACT-01 的 Markdown/文本，其他格式接入后再定义验收。

## 账号与异常状态（HOME-04）

首页布局、插件配置、插件数据访问范围、输入草稿和任务引用归当前本地账号。切换账号沿用全产品的运行任务处理规则，不能把另一账号的草稿、资料或晚到运行事件显示到当前桌面。桌面展示的同一成果或任务使用已有记录，布局不另存业务事实。

| 状态 | 用户可见行为 |
| --- | --- |
| 首次进入 / 空桌面 | 输入框可直接使用；可以显示预置插件或空桌面提示，不要求先安装或建项目 |
| 未配置模型 | 允许浏览插件；发送任务前提示完成必要配置并保留草稿 |
| 插件没有数据 | 说明尚无数据和下一步操作，正式产品不填入虚假任务或成果 |
| 插件加载失败 | 就地显示错误与重试，其他区域仍能使用 |
| 引用失效 / 权限撤销 | 标出失效的具体引用，允许移除或重新授权；不继续读缓存冒充当前有效资料 |
| 运行时断开 | 保留输入和已显示过程，标记真实连接状态，重连后核对任务状态，不把重连当作任务完成 |
| 关闭 / 重启 | 恢复布局及历史；运行任务按全产品退出策略处理，不因隐藏插件或关闭预览而停止 |

## 暂不定义的内容

通用插件从哪里获取、如何安装与升级、市场和分发方式、第三方开发协议、收费机制及底层运行架构后置。首页添加触发 Skill 开发、产物 Pin，以及定时任务完成后渲染数据的方向已明确；具体 Skill 内容、组件执行方式、后台驻留、漏跑补偿、任务并发和首期默认插件组合仍待细化。

## 下一版 Demo 的验收建议

- 打开首页就同时看到输入框和插件桌面，不需要点击“进入项目”或逐级打开文件夹。
- 桌面每个可见业务单元都是插件；任务、资料和成果以插件形式承载，取消独立固定的第三个任务区域。
- 从资料插件引用内容，提交任务，在任务插件中处理授权，并从成果继续修改，全程保留在首页。
- 插件可以排序、收起、隐藏再恢复；数据不会随布局操作被删除，重启可恢复布局。
- 空状态、插件错误和等待授权各有明确表现；账号切换后草稿和插件数据不串用。
- 从文件或网页产物 Pin 到首页，点击可访问目标，取消 Pin 不删除原始产物。
- 点击首页“添加”，输入框展示开发 Skill，描述需求、生成组件、预览并 Pin 的链路可走通；样例数据明确标记。
- 小组件能演示首次无数据、更新中、成功、失败保留旧数据和暂停；任务完成后更新展示与时间。
- Pin 状态与调度启用状态可区分；原型流程通过不等于真实调度、Skill 开发和后台运行已实现。
- 通用插件安装入口、商店或插件包格式不作为本轮 Demo 验收项。

以上是拟定的交互验收，不是已完成测试。Demo 与工程的状态见[对应表](../demo-map.md)和[确认记录](../approval.md)。
