# DSH 内置模式：行为、原理与使用场景

> 所属：[产品大纲](../outline.md) · 支柱一「灵活且自进化的 Harness」（参考资料） · 功能 ID：HARNESS-04.x 的上游依据 · 功能项与进度见[模式管理](harness-modes.md#功能项与进度)。

核查基线：本产品安装的 `@deepseek-ai/dsh-agent-presets@0.1.6-alpha.2`，2026-09-23；2026-09-26 升级到 DSH 0.1.7-rc.2 后复核，四种模式的插件行不变（仅创造模式的插件管理条件与创造 Skill 位置随包调整），实际工具数为标准 26、PTC 26、极简 1、创造 29。这里说明该固定版本的实际装配，不将上游未来能力或产品设计当作已交付功能。自定义模式设计见[模式管理方案](harness-modes.md)。

## 模式决定什么

模式是一套 Agent 工作配置：工具与 Skill、指令与上下文处理、工具呈现方式，以及可选的装配开发能力。它不训练或切换模型权重，也不是“普通 / 高级 / 最强”的等级。模型和推理强度单独选择，同一个模型可以在四种模式下运行。

运行时的公共步骤仍为：接收输入 → 构建模型上下文 → 模型回答或请求工具 → Harness 执行并记录工具结果 → 模型继续处理 → 完成或等待用户。模式改变其中提供的上下文、可用工具及调用形式；存储、模型路由、沙箱和审批等由共享 Host 提供。

## 标准模式：通用的工具使用方式

模型看到文件读写、搜索、Shell、网页检索等独立工具的说明和参数，可以按任务决定调用哪个工具，再根据返回结果决定后续动作。安装的 Skill、工作区指令、计划、目标、子 Agent 和上下文压缩插件共同提供支持。具备这些能力不代表每项任务都会调用全部能力。

例如“整理 20 份会议纪要并输出待办报告”：模型先查看目录与内容，再决定是否调用整理 Skill、检索补充资料，最后写入文件并交付。执行过程可按工具展开，便于用户理解、纠正和审批。独立工具也可能被并行调用，标准模式不等于只能串行。

原理是 preset 中的插件向当前模式的作用域注册工具和提示词；模型通常直接看到每个工具的函数定义。长任务可使用该装配中的上下文压缩。文件、Skill、终端等调用仍受实际权限约束。

适合作为默认模式，尤其是需要边做边判断、工具种类不同的任务。代价是工具说明和多轮结果可能占用较多上下文；任务仍可能失败，工具多不能保证质量更高。

## PTC 模式：用程序组织工具调用

PTC 表示程序化工具调用。用户依然用自然语言提需求，代码由模型生成；不是要求用户编程。固定版的 PTC 模式与标准模式拥有大量相同能力，但模型主要通过 `run_code` 执行 TypeScript 程序，再在程序中调用生成的工具 SDK，而不是直接逐个发送原生工具调用。

同样整理 20 份会议纪要，模型可以写程序完成“列出文件 → 循环读取 → 提取结构化信息 → 汇总”，把需要模型进一步判断的信息返回。循环、条件和中间数据处理可放在程序里；独立步骤还可以编排并行，但具体工具的执行约束仍有效。

原理是 `dsh-agent-tool-presentation` 将工具呈现设为 `ptc`，底层运行时提供代码执行及工具代理。固定模板关闭了普通 `workflow` 工具，避免与 `run_code` 并列两套模型编排入口。工具注册表仍在，原有工具权限和记录机制仍需遵守；PTC 不提供额外授权，也不让多步操作自动具备事务或失败撤销能力。

适合可程序化的重复操作、批量处理和数据整合，可能减少模型往返与不必要的中间输出。若每步都需新的语义判断，仍要返回模型继续推理；脚本本身也可能有错误。因此 PTC 不保证更快、更便宜或更准确，应通过真实任务比较。

## 极简模式：固定提示词与持久终端

固定版极简模式给模型一个完整的简短系统提示词，主要暴露持久 Shell：当前 macOS 使用 bash，Windows 使用对应 PowerShell。模型通过命令读取文件、搜索、运行脚本和使用已安装程序；Shell 内的工作目录与状态可跨调用保留。

同样整理会议纪要，模型需要自行选择命令或编写脚本来读取、处理和输出文件。它没有标准装配里的独立 Skill 加载、网页搜索与上下文压缩支持，但终端仍可能通过已安装工具完成这些工作的部分内容。实际可做什么还取决于本机程序和权限。

原理是 persona 使用 `complete: true` 和 `includeRuntimeContext: false`，抑制常规提示词追加及运行时上下文注入；持久终端注册在受作用域管理的组件内，继续使用 Host 的沙箱和进程实现。

适合明确的命令行任务、受控实验和观察模型自身的命令行解决能力。它不是安全程度更高的模式：一个 Shell 可以执行很多动作，工具少不等于权限小。没有标准压缩装配，也使它不宜直接作为长期办公会话的默认选择。给它增加 Skill 和动态指令时，需要同步改变相关插件及提示词策略，而不是只勾选一个 Skill。

## 创造模式：创建或改造 Agent 的装配

创造模式的“创造”主要指 Agent/preset/插件开发，并非专门写文章或画图。它在标准能力基础上提供装配创作指导、相关 Skill、运行时检查，以及 `plugin_manager` 工具。

例如“创建一个每次输出都附来源的研究模式”：Agent 可以检查现有装配，复制 preset，编写指令与 Skill，检查新的配置。若任务需要尚未安装的能力，还可能编写或安装插件。具体结果仍需加载和真实任务验证，不能只因为文件已生成就宣称新能力可用。

原理是额外的提示词和 Skill 告诉模型如何理解 Cordis 的插件、服务和作用域，并开放相应检查与管理工具。部分插件管理会修改 profile 共享配置，影响同一 Host 下的其他会话；上游要求相应审批或权限，可能还需要重启。它不是对当前对话无影响的“随便改一下”。

适合制作、诊断或扩展模式。普通办公任务不需要默认暴露这种能力。它提供生成或修改的手段，但未自动解决“改进目标是什么、怎样验证更好、怎样避免退化”；Focus Workspace 规划的反馈、候选、比较验证、采用及回退负责补齐这些环节。创造模式运行中的修改也不会天然进入本产品的版本记录，需显式导入候选并验证后纳管。

## 四种内置配置不是互斥的能力等级

标准与极简在能力集合、提示词和上下文策略上差异较大；PTC 主要改变工具调用形式；创造主要增加装配开发能力。因此，自定义研究模式可以使用直接工具调用，也可以使用 PTC；新增一种模式不需要新增一种执行循环。产品以受验证的字段与依赖规则装配，避免把一项开关误当成整个模式的全部差异。

当前默认建议仍是标准模式；可程序化的批处理再比较 PTC；明确命令行或实验任务使用极简；创建与维护能力时使用创造。具体效果由任务、模型、指令和工具共同决定。

## 本地依据

- 安装依赖的 `dsh-web-app/presets/{standard,ptc,minimal,cordis}.patch.yml`：四种模式的实际插件与配置（0.1.7 起；0.1.6 为 `dsh-agent-presets/presets/*/agent.cordis.yml`）。
- 安装依赖的 `dsh-agent-preset-registry/README.md`、`dsh-agent-preset/README.md`：preset 的注册、修订保留及空会话切换规则（0.1.7 起）。
- 安装依赖的 `dsh-agent-tool-presentation/README.md`：`native`、`ptc`、`both` 的工具呈现与运行时依赖。
- 安装依赖的 `dsh-plugin-manager/README.md`：插件管理的 profile 影响范围与授权要求。
