# 对话与任务

> 所属：[产品大纲](../outline.md) · 支柱二「工作台式任务管理」的 P1 运行面 · 功能 ID：HOME-01.1、CHAT-01、CHAT-02、TASK-01.1、TASK-01.2、ARTIFACT-01.1、CHAT-03 · 功能项与进度见下文「功能项与进度」。

## 功能项与进度

状态含义见[写法规范](README.md#功能项与状态)。本表是这些功能 ID 的阶段与状态的唯一来源。

| ID | 功能 | 阶段 | 状态 | 完成条件 |
| --- | --- | --- | --- | --- |
| HOME-01.1 | 输入、发送、流式回复、继续对话 | P1 | 开发中 | 真实 DSH 响应；区分发送中、执行中、完成与失败 |
| CHAT-01 | 新建会话、历史列表与重启读取 | P1 | 开发中 | 重启后内容可读，不暗示中断执行已自动恢复 |
| CHAT-02 | 工作区选择、文件引用与范围提示 | P1 | 开发中 | 明确本次可读目录与选中文件，引用可追溯 |
| TASK-01.1 | 工具执行、进度和失败信息 | P1 | 开发中 | 展示真实调用及结果，区分任务失败和连接中断 |
| TASK-01.2 | 审批、提问、停止及错误后继续 | P1 | 开发中 | 允许或拒绝具体动作、回答问题、中止任务，重试不自动重放外部副作用 |
| ARTIFACT-01.1 | 对话内成果查看、打开与继续修改 | P1 | 开发中 | 实际文件生成并关联来源任务 |
| CHAT-03 | 多任务并行、队列与资源管理 | P2 | 待细化 | 工作台式任务管理需要的并行与队列规则（修订 13 由“后续”调整为 P2） |

对话是 P1 唯一的做事入口，也是 Harness 底座的运行面：每一次真实任务产生执行证据和反馈，供[运行观测](harness-mode-editor.md#模式内观测)与[自进化](self-evolution.md)使用。

## 功能与交互

| 功能 | 用户操作与结果 |
| --- | --- |
| 开始任务 | 选择工作区、引用文件、输入需求；可查看本次使用的能力配置摘要 |
| 执行过程 | 流式显示回复，展开真实工具调用与结果，区分执行中、等待用户、完成和失败 |
| 人工控制 | 对具体动作批准或拒绝，回答补充问题，停止任务；失败后保留已完成动作和错误信息 |
| 成果 | 查看或打开实际生成的文件，继续对话修改；成果能返回来源任务 |
| 历史 | 新建、查找、打开和继续会话；重启后读到历史，中断任务不能伪装成自动恢复 |
| 结果反馈 | 标记“可用 / 需要修改 / 失败”，补充原因；选择只修改当前成果，或把纠正用于“改进做法” |

首期围绕一个前台任务优化体验，不额外建设并发队列管理。每次运行保留实际配置、模型和能力来源，方便解释结果和后续比较。用户不必填写反馈才能继续工作。

## 与 Harness 的关系

保留新建与历史会话、输入与流式回复、工作空间和文件引用、工具执行记录、审批、补充信息、停止任务、成果查看与继续修改。对话能查看本次采用的 Harness 版本和可用能力摘要，能力名称可定位到管理详情。P1 默认一个前台执行任务，不扩展桌面 Pin、知识整理或定时调度。

新对话优先使用显式选择的模式及具体版本，未选择时用账号默认；发布模式不自动修改默认。已有会话显示自己的配置版本；管理页变更不静默替换运行中的装配。建议第一期以“使用新配置新建对话”作为明确切换方式，旧会话使用旧配置继续前须核验旧版本可用性，无法重建时说明原因，不暗中套用最新配置。
