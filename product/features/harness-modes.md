# Harness 模式管理与自定义设计

> 所属：[产品大纲](../outline.md) · 支柱一「灵活且自进化的 Harness」 · 功能 ID：HARNESS-04.1～04.4、HARNESS-05 · 阶段与状态以[大纲功能清单](../outline.md#七功能清单)为准。

方案修订 12，2026-09-23。状态：已获授权并交付 alpha.5 基础实现，完整目标与本次实现差距见 [实施规格](harness-mode-editor.md)。本页定义交互与工程细则。用户已明确需要多套可自定义模式；具体字段、默认规则和分期为本方案建议。

## 产品概念：统一称为模式

**一种模式就是一套完整的 Harness 工作配置。** 标准、PTC、极简和创造是 DSH 提供的四种内置模式，首次使用即可选择；用户可以新增自己的模式，也可以定制内置模式的细节。界面统一使用“模式”，来源、版本和实际配置在详情中解释。模式的版本和本次实际配置是详情信息，不是另外两个产品入口。

“内置”表示配置来源，“默认”表示新对话未手选时用哪一个；四个内置模式都可用，但账号只能有一个当前启动默认，初始为标准模式。用户模式与内置模式在同一个模式选择器里使用，能力和权限不能仅由来源标签推断。

详细区别见[四种内置模式说明](harness-builtin-modes.md)。产品层模式除 DSH preset 的指令和插件外，还记录默认模型策略、权限建议、版本与账号归属。新增模式不要求编写新执行循环；底层继续生成和加载 DSH preset。

### 新增、编辑内置与恢复

| 操作 | 产品行为 | 保存方式 |
| --- | --- | --- |
| 新增模式 | 选择一个内置或已有用户模式作为起点，命名并编辑；可逐步移除和增加受支持能力 | 新的稳定模式 ID，记录来源模式及确切版本，后续独立维护 |
| 编辑用户模式 | 在原模式独立草稿中调整，检查和发布新版本 | 模式 ID 不变，新增不可变 revisionId |
| 定制内置模式 | 在内置行直接点“编辑”，发布后显示“标准 · 已定制”等状态，无需强迫用户先理解复制流程 | 在本地创建该内置模式的用户定制版本，底层写新 presetId，不改依赖内原版 |
| 恢复内置原版 | 对比差异后将该模式当前指针恢复到固定 DSH 版本的原版 | 定制版本留在历史；已开始的会话保持原版本，可再次恢复定制 |
| 另存为新模式 | 从当前原版或定制版本复制，起名“资料研究”等 | 新模式，与来源不自动继承更新 |

内置模式的定制归当前账号，不能直接修改安装包；界面保留模式名称并展示“内置 / 已定制 / 用户创建”和来源版本。恢复与回退不删除历史。普通用户模式可归档，内置原版始终可找到；关闭其装配开发能力不等于删除内置模式。上游升级时先展示原版变更，已定制版本不自动被覆盖，不做隐式字段合并。

## 页面与主要链路

保留左侧“对话 / Harness”，字体和既有视觉风格不变。Harness 页进入“模式”列表，详情在同页主区域打开。每行显示名称、用途、来源模板、当前可用版本、模型 ID、能力摘要及“默认 / 有草稿 / 待验证 / 不可用”状态。顶部有搜索、新建；单行可进入详情、开始对话、复制、设为默认；用户模式可归档，内置模式可恢复原版。列表初始展示四个内置模式，可按“全部 / 内置 / 我的”筛选；内置与自定义模式使用同一详情结构。另用唯一“启动默认”标记说明默认选择。

详情顶部固定模式名、所看版本和查看范围：“模式配置”或“对话实际配置”。下方为配置、实际运行、试跑、版本。装配分为基本信息、模型、指令与上下文、工具调用方式、Tools、Skills、MCP、Subagent、权限；不以数十个底层插件开关作为默认页面。高级详情提供实际 Cordis 清单和来源，只读。

1. 新建：选择已有模式作为起点，命名并写用途，产生独立草稿；复制时明确来源版本，来源不限制以后受支持字段的调整。
2. 装配：选择模型、编辑附加指令、选取能力与权限建议，立即显示可确定的缺项和冲突。
3. 检查：先做静态校验；需要启动 MCP 或加载插件时明确列出执行内容。展示真实加载、工具发现和失败原因，不用“已保存”代替“可用”。
4. 试跑：创建独立测试会话，用准备发布的候选快照执行一个真实任务；标记模型费用和可能的工具副作用，沿用正常审批，不在试跑时扩大权限。
5. 发布版本：展示与基准版本的差异、检查结果和试跑情况；通过必需加载检查后保存不可变版本。真实试跑未执行可手动发布，但显著标记“任务效果未验证”；自动改进候选仍遵循 EVOLVE-03 的验证门槛。
6. 使用：发布只更新这套模式的当前版本，不改变账号默认。另行点击“开始对话”或“设为默认”。已有会话和其他模式保持原绑定。

草稿离开页面前保存或明确丢弃；所有编辑及检查结果显示所属模式和草稿修订号，避免切换模式后误写。依赖变更后原有检查结果标过期，不能复用过期的“通过”。

## 可装配内容与实现范围

| 装配项 | 第一版多模式支持 | 限制与后续 |
| --- | --- | --- |
| 来源模式 | 内置四种及用户已有模式均可作为起点，记录来源版本 | 来源只用于追溯和初始值，不把模式永久锁死在四类里 |
| 工具调用方式 | 直接调用（native）或程序化调用（PTC），说明差异、检查运行时与冲突 | 上游还提供 both；首版不开放，以免增加重复工具入口和验证组合 |
| 模型 | 从已配置连接中选 provider、实际 model ID、默认推理强度；支持跟随账号默认或固定选择 | 凭证留在连接设置，不复制进模式；模型显示名与请求 ID 同时显示，别名转接只标为官方说明 |
| 指令与上下文 | 编辑模式附加指令；选择是否加载已支持的工作区指令及显式上下文来源；预览来源、作用域和顺序 | 展示固定完整提示词或组合注入策略；极简要启用 Skill/工作区指令，必须显式调整策略并增加依赖，不能让输入静默无效 |
| Tools | 从当前安装且可被 preset 装配的提供方选择，查看用途与参数 | 按实际支持的单位启停；不能承诺任意单工具开关，更不把关文件工具当作禁止终端读文件 |
| Skills | 从账号能力库选入、启停，发布时固定本地 Skill 内容版本 | 修改来源生成新版本；已有模式不自动跟随，显示可升级提示 |
| MCP | 从账号连接记录引用 stdio 服务，模式决定是否装配；保存命令与参数快照 | 凭证只保存引用；可执行程序和远端服务可能变化，记录这一限制；HTTP/OAuth 保持后置 |
| Subagent | 启停固定版支持的内置委派能力，显示继承行为 | 当前子 Agent 加入父级装配；不能先画出“任意选另一套 Harness 派发”的无效控件，异构子 Agent 映射留 P2 验证 |
| 权限 | 保存新会话的权限建议并在启动前显示实际权限 | 更宽权限遵循正常授权流程；技能或模板不授予额外权限，不能在发布模式时静默开启高权限 |
| 高级插件与参数 | 展示实际插件、来源、依赖和已支持参数 | 任意 YAML/JS、插件安装和共享 Host 服务变更不在第一版模式编辑器内执行；上下文压缩仅编辑已支持策略与已验证参数，不宣称可任意改算法 |

账号能力库负责维护可选资产和连接；模式只管理选择、参数与固定版本。首版可作为装配面板内的选择器实现，不新增“市场”主导航。复制模式默认引用相同资产版本，但草稿选择独立；更新共享资产不会悄悄更新所有模式。

内置模式是完整起点，不承诺四种模式的任意部件都能相互拼接。标准与 PTC 的主要差异是工具呈现方式；极简缺少标准 Skill、上下文压缩等插件；创造的插件管理可能影响共享 Host。把共享 Host 插件加入某模式，必须明确为独立的安装或运行时变更，不能伪装成仅影响该会话的局部开关。第一版通过能力依赖矩阵检查编辑，加载检查验证所选模式确实可运行。模式来源不是永久限制；实现未覆盖的转换明确显示原因并禁止发布，不能显示保存成功却仍按旧模式运行。

## 编辑器的配置细节与依赖联动

编辑器采用左侧模式列表、右侧详情，详情内有“配置 / 实际运行 / 试跑 / 版本”。配置默认展示常用项，底层插件与来源收在高级详情；不要求用户先学 YAML。右侧摘要显示所选模型、工具调用方式、能力数、权限及未解决依赖，参数显示“当前值 / 来源 / 原版值”。能力说明支持查看底层实际装配。

| 用户调整 | 编辑器必须说明和执行的依赖检查 |
| --- | --- |
| 从直接调用改为 PTC | 检查 PTC runtime；替换唯一的工具呈现声明，按固定版策略处理重复 workflow 入口；发布差异需列出关联变更 |
| 在极简来源上增加 Skill | 检查 Skill 发现/加载工具及提示词策略；如果固定完整提示词阻止注入，提示切换到组合注入并列出新增插件；不自动伪装为原版极简 |
| 增加或关闭上下文压缩 | 检查所需插件及依赖，说明长会话影响；仅开放固定版验证过的配置，不提供虚假的压缩阈值控件 |
| 关闭终端但保留终端型工作流 | 列出可确定的依赖并要求处理；无声明依赖的 Skill 标为待试跑验证，不猜测兼容性 |
| 增加装配开发能力 | 解释创造相关工具的 profile 影响与审批；本地模式字段更新与安装/修改共享插件必须分开操作 |

关联变更以可审阅差异呈现，用户接受后进入草稿，不在勾选时悄悄写共享配置。暂不支持的能力转换可以保留为草稿缺项，但不能成为“检查通过”的可用版本。选择某种来源后完全改掉配置，仍以用户模式或“内置 · 已定制”展示，不冒充未改动的官方模式。

示例“研究模式”：从标准开始，命名研究模式；固定 `deepseek-flash`，写“结论附来源”的附加指令；选网页工具、资料 MCP 和研究 Skill，关闭无关子 Agent；选择直接调用或 PTC；设置只读权限建议。检查、试跑和发布后，它与四个内置模式一同出现在对话模式菜单。这个示例只解释配置方法，不创建真实 MCP 或权限。

## 对话选择、默认与覆盖

输入框附近提供“模式”选择器，显示例如“资料研究 · v3”；旁边的模型选择器显示名称与实际请求 ID。模板信息在模式详情解释，避免同时要求用户选择模式和模式两套互相冲突的配置。

新会话模式优先级为显式选择 > 工作区默认 > 账号默认 > 产品标准模板；工作区默认属于 P2，第一版只有显式选择和账号默认。点击发送时将模式当前版本解析为具体版本 ID，保存绑定；有新版本时提示，不让已有会话自动升级。只有空会话允许更换模式；有消息后使用“以另一模式新建对话”，需要携带资料时预览选定摘要与附件，不把旧工具日志直接移植到新装配。

模型优先级为本次明确选择 > 模式固定模型 > 账号默认；模式选择“跟随默认”时，在任务开始记录解析后的真实 ID。更改对话模型或推理强度不修改模式，显示“本次覆盖”；后续每次运行记录实际模型参数。更改到另一模式时重新解析默认，并在发送前展示结果，不沿用来源不明的上一次覆盖。权限另按用户选择及产品允许范围解析，不因上述优先级扩大授权。

第一版提供账号默认模式。设置默认只影响未来未显式选择的会话。归档的模式从新会话列表隐藏；历史版本和会话仍可读、可在依赖可用时继续。归档当前默认前必须选择另一个可用默认；恢复归档不自动设回默认。首版不提供硬删除，避免破坏版本与历史关联。

## 版本、异常和自进化

每套模式拥有独立版本列表：版本号、来源、变更摘要、验证、使用会话、发布时间。回退先校验旧版本依赖，再把该模式当前指针切回旧版本并记录原因，不覆盖或删除版本；正在运行的对话继续使用原绑定。模式恰好是账号默认时，未来会话使用它恢复后的版本；其他模式不受影响。

保存草稿、静态校验、加载成功、工具发现、真实调用和任务效果是不同状态。MCP 断开时显示受影响模式与实际状态；缺失模型、Skill、程序或模板依赖时，阻止依赖它的新会话启动并列出修复步骤，不悄悄降级。运行中服务故障作为调用失败显示，历史仍可读。

两个窗口编辑同一草稿、或候选生成后用户又发布版本时，提交必须核对基准修订号；冲突显示差异，要求基于新版本重新合并检查，不能覆盖后写入内容。进化候选关联具体模式与基准版本；同一 Skill 被多模式引用时，只升级明确采用的目标模式，其他模式收到可选更新提示。

## 技术架构与数据

继续复用 Electron + 独立 Node + `dsh --profile web`，由产品 Host 插件管理业务，不改 Agent 执行循环。DSH 的 Host 持有模型路由、存储、沙箱/审批和服务注册表；Agent preset 提供每个模式的插件、提示词及工具注册。多个会话可加入同一 preset 的挂载作用域，各会话状态分别保存；这不是“一套 Harness 启一个 Electron”。

| 产品对象 | 必需字段和责任 |
| --- | --- |
| HarnessDefinition（界面称模式） | accountId、稳定 harnessId、名称、用途、来源类型、builtInKey（可选）、原版版本、本地定制标记、归档状态、当前已发布 revisionId |
| HarnessDraft | harnessId、baseRevisionId、draftRevision、模板版本、装配字段、最后保存时间 |
| HarnessRevision | 不可变 revisionId、harnessId、父版本、模板与 DSH 版本、生成的 presetId、模型策略、指令/Skill 快照、Tool/MCP 配置、权限建议、内容校验值 |
| CapabilityAsset | accountId、资产 ID、类型、来源、版本；连接凭证只保存引用，敏感参数不写入普通索引 |
| SessionBinding / TaskRun | sessionId、harnessId、revisionId、实际 presetId、工作区；每次运行保存实际模型 ID、覆盖、权限和可观测依赖状态 |
| Validation / Adoption | 目标模式和候选版本、检查输入及结果、来源任务、采用/回退者和时间、基准版本 |

结构化装配经显式转换生成完整的 `agent.cordis.yml` 与 `preset.yml`，调用 DSH 的复制、加载、会话创建及查询服务。每个产品版本使用新的 DSH presetId，不直接修改被历史会话引用的目录。内置原版以独立 baseline 记录，其本地定制版本使用新的 presetId。恢复原版只是切换该模式当前指针；自定义模式的来源版本只供追溯，不在运行时做继承或合并。模板版本升级是一次可比较、可验证的显式迁移，不自动覆盖用户模式。

发布顺序：冻结候选及资源 → 静态检查 → 在独立检查会话加载并检查依赖 → 可选真实试跑 → 检查基准未变 → 原子记录发布版本与当前指针。失败保留旧版本和明确错误；中断候选不出现在普通选择器。设默认是另一个原子操作。第一版可延续账号级 JSON 存储与串行队列，另加修订比较及中断恢复记录；只有查询与事务需求确实超过现状时再迁移 SQLite。

现有 `state.json` 只有一份全局 draft 和线性 versions，且 `applyDraft` 固定复制 standard 并自动设默认。迁移先备份并校验 schema；依据显式旧版本链建立一套“原工作配置”，保留旧 presetId 与会话引用，当前草稿归入该模式；没有历史版本时建立待发布模式并保留上游默认。不能凭名称猜测多套模式或虚构历史模型参数，旧记录缺失项标未知。底层还存在产品未管理的 preset 时作为只读来源列出，可显式复制纳管，不删除。用户数据迁移在实现阶段单独验收。

开发前需验证：固定版本会话创建 API 对模型与权限的原子配置顺序；标准/PTC 字段兼容性；极简/创造的可编辑字段及 Host 影响；实际会话视图不能用默认 preset 的任一运行实例代替。若上游只支持继承父装配的子 Agent，界面保持该限制，不默认修改内核。

## 分期与验收

P1 多模式基础：创建、复制、重命名、归档；四个内置模式直接可选、内置定制与恢复、用户模式新增；已支持装配、模型/指令及权限建议；独立草稿与版本；手动选择及账号默认；真实配置查看、加载检查、试跑、发布与回退。极简/创造同样进入编辑器，字段及跨策略转换仅在实现并验证后开放；未实现项明确标记，不将起始模式硬编码为永久权限。P2：工作区默认、脱敏导入导出、复杂 Subagent、更多受控插件与高级参数。任意流程画布和改写执行循环继续后置。

1. 四个内置模式均可直接选择；定制标准并发布，不改安装包原版，恢复原版后旧会话仍绑定原定制版本。

## 按需组合（HARNESS-05，修订 13 草案，待对齐）

**问题。** 模式是长期配置；真实任务常常只需要临时多一个 Skill 或 MCP。现在必须“编辑模式 → 检查 → 发布 → 新建对话”，对一次性需求太重，用户会倾向于把所有能力塞进一个大模式，失去“按需组合”的意义。

**行为。**

1. 空会话发送前，模式选择器旁提供“本次组合”：在所选模式版本上临时增减 Skill、MCP 与工具组，只能选择已通过加载检查的资产。
2. 发送时把“模式版本 + 本次增减”解析为一个实际组合并绑定会话；会话显示“研究模式 · v3 + 1 项临时能力”。有消息后不能再改，与模式的空会话切换规则一致。
3. 任务结束后可“另存为新模式”或“提交到本模式草稿”，之后走正常的检查、试跑与发布；模式本身的已发布版本不被临时组合改变。
4. 同一能力在同一模式上被临时追加多次时，记录为改进机会；P1 只记录并在模式页提示，P5 再由 Agent 主动提出候选（EVOLVE-05）。
5. 后续可由 Agent 根据任务描述推荐模式与临时能力，用户确认后生效（待细化，P1 仅手动）。

**实现约束（待工程验证）。** 固定版 DSH 的每个 preset 是不可变目录，临时组合若每次生成新 preset，需要验证创建耗时和清理策略；上游 0.1.7 新增的 profile YAML 声明 Agent 组合（#4569）可能提供更轻的实现，在 TASK-030 中评估。

**验收。** 临时追加 Skill 的会话实际调用该 Skill；所用模式的已发布版本不变；另存的新模式与临时组合一致；旧会话能追溯实际组合；未通过检查的资产不可选。

**待确认。** 按需组合是否进入 P1；推荐组合由 Agent 做还是先只做手动。
