## 一、定位

**面向超级用户的开源个人 Agent：以 DeepSeek Harness 为底座，提供一个灵活、可控可见、能自进化的 Harness，并在其上构建工作台、主动性、系统连接、个人知识库和 Agent 网络。**

核心亮点是 **自进化** 与 **可控可见**：看得见 Agent 如何工作，才能控制它；控制得住每一次改变，才能放心让它进化。

## 二、目标用户

因 AI 而具备开发能力的高级知识工作者：不是职业开发者，但已经能借助 AI 写脚本、写 Skill、接 MCP、改配置；同时使用多个 AI 工具，有长期积累的方法论和资料。他们要透明和控制力，要纠正一次就能沉淀下来，不要黑盒和每次重讲背景。首个实例用户是项目作者。

## 三、产品原则

1. **真实优先**：只有真实运行和真实任务证据能推进进度；Demo、模拟与加载成功不算完成。
2. **可见才可控**：配置、实际加载、实际调用与任务效果分别展示，未知就标未知。
3. **改变可追溯、可回退**：版本不可变，旧会话不被静默改变，改进先验证后采用。
4. **经验属于账号**：偏好、Skill 改进和资料属于用户，不写入产品代码。
5. **上游优先**：DSH 已有的能力直接用，重叠能力向上游迁移。
6. **方案先行**：先确定方案并确认，再写代码。

### 支柱一 · 灵活且自进化的 Harness

用户能按任务组合模型、指令、Tools、Skills、MCP 与 Subagent，看清每一次任务实际用了什么，并把纠正变成可验证、可回退的改进。这是选择 DSH 的原因，也是 P1 的全部重点。

| 模块 | 基础描述 | 当前进度 |
| --- | --- | --- |
| [模式管理与按需组合](features/harness-modes.md) | 一个模式就是一套 Harness 配置：四种内置模式加自定义模式，独立版本；按需组合允许单次任务临时增减能力 | 模式列表、草稿、发布、恢复已实现；每模式固定模型与按需组合待做 |
| [能力装配与现状](features/harness-capabilities.md) | 装配 Tool、Skill、MCP、Subagent，展示实际状态与来源；上下文可视让用户看到每次请求实际带了什么 | 装配与实际清单开发中；上下文可视待做 |
| [自进化](features/self-evolution.md) | 反馈 → 候选 → 验证 → 采用 → 回退的受控闭环；P1 用“产品方案与行动清单”真实任务验收 | 配置候选闭环已用算术样例跑通；Skill 候选与真实任务验收待做 |

### 支柱二 · 工作台式任务管理

对话负责做事，工作台负责组织任务、成果与资料。P1 只交付对话，作为 Harness 的运行面；工作台随 P2 交付。

| 模块 | 基础描述 | 当前进度 |
| --- | --- | --- |
| [对话与任务](features/conversation.md) | 发起任务、查看执行、审批、停止、查看和继续修改成果、历史 | 已接入 DSH 官方对话界面；审批/停止/成果完整链路待专项验收 |
| [工作台](features/workbench.md) | 输入框与同页插件桌面，文件/网页 Pin，多任务管理 | 设计已有，未开发 |

## 五、技术底座

执行循环、模型、工具、会话日志、Skill/MCP/Subagent 和审批全部复用 DSH；Focus Workspace 通过自己的 Host/Client 插件负责模式版本、观测、自进化闭环、账号化经验和产品体验。当前锁定 DSH 0.1.6-alpha.2。详见[技术架构](../engineering/architecture.md)与[上游跟进](../engineering/upstream.md)。

## 六、分期路线

| 阶段 | 版本 | 交付 |
| --- | --- | --- |
| **P1 · Harness 底座** | v0.1 | 支柱一全部 P1 模块，对话作为运行面，一次真实任务的自进化闭环 |
| P2 · 工作台 | v0.2 | 工作台、多任务管理、多账号、复杂 Subagent、模式导入导出 |
| P3 · 主动性与系统连接 | v0.3 | 主动性 AI 与系统连接扩展 |
| P4 · 知识库 | v0.4 | 知识库 |
| P5 · 自进化自动化 | v0.5 | 批量评测、主动发现改进机会、限定范围自动采用 |
| P6 · 网络与生态 | v0.6 | Agent 协作与生态分享 |

版本号不是日期承诺，P2 之后的顺序按真实使用调整。
