# 可编辑模式 · 修订 12 实施规格

日期：2026-09-23。用户已明确授权更新方案并实现；关联 HARNESS-04.1/04.2/04.3、EVOLVE-01/02/03/04。

## 功能与交互

Harness 首页列出标准、PTC、极简、创造四个内置模式，以及用户从这四种类型创建或复制的模式。类型表示起始装配；没有第五种执行内核。每个模式都有自己的名称、草稿修订、当前发布版本、观测设置和进化设置。选中模式进入编辑、运行观测、自进化、版本四个子页。

编辑采用分组表单，提供同一结构的高级 JSON 编辑。JSON 只承载允许的配置字段，不接受任意 JavaScript、插件路径或原始 Cordis 程序。后端以 Zod 做同一份校验；两种编辑方式共享保存、差异、加载检查及发布服务。参考 [react-jsonschema-form 的受控表单代码](https://github.com/rjsf-team/react-jsonschema-form/blob/main/packages/core/src/components/Form.tsx) 和 [JSONEditor 的编辑器示例](https://github.com/josdejong/jsoneditor/blob/develop/examples/01_basic_usage.html)，本次字段规模有限，复用现有 React 与 Zod，不引入通用拖拽平台。

可编辑字段包括名称、附加指令、直接调用/PTC 工具呈现、文件/终端/网页/Subagent 工具组、本地 Skill、stdio MCP、创造模式的原生配置工具、观测开关、进化开关及改进目标。极简保留持久终端，可按需添加文件、网页、Skill、MCP；补充工具后不再是官方原版的单工具组合。依赖和能力以真实加载检查为准。完整角色/任意插件开发、沙箱策略编辑、每模式默认模型与任意参数后置；模型继续在对话的官方选择器中明确选择，编辑器不提供无效的模型开关。

保存只更新当前模式草稿。发布先复制该类型的官方 preset 为新的不可变目录，生成配置、冻结 Skill、真实创建检查会话并发现工具，成功才更新该模式的当前指针。发布非默认模式不改变账号默认；发布当前默认模式只更新未来会话的默认版本。设为默认是单独操作。内置模式的定制不覆盖官方文件；恢复原版或旧版本不删除历史。旧会话依然使用原 preset。自定义模式可归档，默认模式不可归档。

保存/发布携带草稿修订号；不同窗口与过期候选产生冲突时阻止覆盖。页面提醒未保存离开。版本页面显示配置差异和历史；官方对话选择器展示底层版本，新对话默认解析到已设默认的最新版本。按逻辑模式折叠对话菜单中的历史版本属于后续 UI 集成，不声称此版已完成。

## 模式内观测

观测开关控制产品观测页是否汇总该模式的会话证据，不关闭 DSH 的基础运行日志。观测页展示当前发布版本的实际插件、可调用工具和 Skills；会话列表按实际 preset 归属过滤，查看指定会话的运行状态、实际模型、工具调用/失败与事件数量。没有模型请求时显示未调用，不用配置值填充实际值。检查会话明确标记。历史会话的观测使用其自身的版本。大规模查询与成本/耗时统计后置。

## 模式内自进化

每种模式单独开启受控进化并填写目标。第一版闭环是：选择真实来源会话并记录反馈 → 创建改进任务（调用现有 DSH 对话，要求输出完整配置 JSON） → 从结果导入候选或手工编辑候选 → 记录同一任务下的基准/候选验证证据 → 人工采用到该模式草稿 → 正常校验发布 → 必要时回退。

生成改进任务会真实调用用户配置的模型，因此由明确按钮发起。任务只生成建议，不自动修改模式；标准模式生成器关闭执行工具，仅使用提供的反馈和配置文本。候选完整配置和来源反馈保存在账号下，基准版本与草稿修订号变化时拒绝采用。验证记录是用户提供的证据，不显示为自动跑分；没有证据不能采用。进化开关不会赋予改写产品 Host、自动执行程序或自动发布的权限。创造模式的原生插件管理能力与此闭环分开，其上游变更不自动纳入产品配置历史。

## 数据与迁移

沿用独立账号目录、串行操作队列及原子 JSON 写入，schema 2 保存 modes、反馈/候选和操作记录。schema 1 原文件备份后迁移为独立的“原工作配置”，保留全部旧 presetId 和草稿；四个官方模式独立初始化。版本目录永不覆盖。观测仅在本地读取日志，模型改进任务仅注入选定反馈与配置，不自动发送整个会话、目录或账号信息。

## 验收

四种模式真实装配；A/B 独立草稿与版本；非默认发布不改变默认；旧会话绑定不变；极简持久终端、创造工具和 PTC 呈现保持有效；表单/JSON 校验一致；错误 MCP/Skill、过期草稿和候选不会覆盖有效版本；迁移保留旧数据；观测不伪造模型调用；候选需反馈和对照证据才能进入草稿；打包并在桌面实际检查。

## 固定版 DSH 的多创造模式兼容

实际补测发现 `dsh-tool-cordis@0.1.6-alpha.2` 每次挂载创造 preset 都重复向 Host 注册同名检查服务，导致内置创造与自定义创造并存时失败。产品构建增加精确版本与代码锚点校验的兼容补丁：按 Host 共享这些只读 provider，以引用计数在最后一个装配释放时清理；工具和提示词继续按 preset 独立注册。此修复不改变 Agent 循环、不删除创造能力；升级 DSH 时必须复核并移除此补丁或重新验证。
