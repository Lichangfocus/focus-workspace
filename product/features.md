## 管理规则

本表是功能范围、目标阶段和实现状态的唯一管理入口；[产品方案](brief.md)解释目标，[页面与交互](experience.md)及[首页定义](home.md)定义完整行为，[Demo 对应表](demo-map.md)记录演示覆盖，[待办](../iterations/backlog.md)跟踪执行任务。功能不因延期而删除，新增或调整先更新本表，再更新相关方案、Demo 和工程任务。

沿用既有功能 ID；一个功能跨阶段时用 `.1`、`.2` 拆出交付项，父 ID 保留。`TASK-01` 是产品功能，`TASK-001` 是迭代任务，两者不能混用。阶段不等于完成状态，也不等于日历承诺。

状态依次为：待细化 → 待对齐 → 可开发 → 开发中 → 待验收 → 已验收；明确后置项为“延期”。“可开发”须有对应方案及 Demo 确认；“已验收”须有真实产品证据链接。上游已有能力和 Demo 模拟成功均不能直接升级实现状态。当前已交付桌面 alpha.4（模型名称与实际 ID）；修订 7 的部分 P1 链路已开发和验证。修订 8 新增条目标记待对齐，不因文档更新变为已实现。实际覆盖与缺口见[迭代 008](../iterations/008-desktop-alpha.md)。

## P1 的交互与验收边界

第一期主要入口为“对话”和“Harness”，本地账号与模型连接作为基础设置。用户已明确这两个功能分区；用户已授权基于该范围开发；当前使用桌面 alpha.2 对齐实际交互，旧 Demo 保留历史参考。P1 在现有两个入口内增加受控改进闭环；首页插件桌面、Pin、小组件、知识库、协同和无人值守自动优化继续后置。

验收链路为：装配一个 Tool、一个 Skill 和一种受支持的 MCP → 校验应用 → 查看实际 Harness 状态 → 用该配置新建对话 → 完成真实任务并追溯调用来源 → 修改或停用能力 → 新对话验证 → 手动回退。同时新增一条：真实成果 → 明确反馈 → Agent 生成 Skill 候选 → 固定任务验证 → 采用 → 新任务使用 → 回退。对话的人工作用控制、历史、成果、账号归属与安装包恢复仍必须通过。具体条件和状态定义以[第一期设计](harness-management.md#第一阶段验收)为准。

Demo 下一版同时展示对话和 Harness 管理联动；旧 Demo 中的能力页及 Harness 示例可作为素材，仍不代表修订 8 新增闭环已实现或通过真实验证。

模式交互、资产共享规则、数据迁移和验收见[模式管理设计](harness-compositions.md)。新增条目均为设计状态；模型 ID 显示的局部交付不代表这些功能已开发。

alpha.5 已验收四类型加载、独立版本、Skill/MCP 发现、指定会话真实观测及候选试跑与采用门槛。每模式固定模型、权限建议执行、完整上下文可视化、对话菜单合并历史版本尚未完成；不将本版等同于全部 P1 完成。
